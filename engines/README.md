# Engines

Status: **CONCEPT catalog; no engine implementations**.

[ARCHITECTURE](../docs/ARCHITECTURE.md) defines observation, evidence, health,
rules, dependencies, capabilities, snapshots, deltas, migrations, repair planning,
backup, repair, verification, rollback, reports, and case-study responsibilities.
These are possible coherent boundaries, not modules to scaffold merely because
they have names.

A future engine entry should document purpose, inputs/outputs, dependencies,
permissions, evidence, status, tested scope, human/machine presentation,
verification, preservation constraints, and limitations. Introduce one capability
when a real case justifies it. Keep diagnosis and mutation separate.
